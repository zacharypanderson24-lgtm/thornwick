# Thornwick: notes for Claude (read this first in every new chat)

Medieval TheoTown-style pixel isometric city builder. Owner: Zach. Hosted from this repo on GitHub Pages and Vercel (https://thornwick-two.vercel.app/, auto-deploys on push to main). ChatGPT makes the art (rules in CHATGPT_START_HERE.md); Claude does the code and reviews the art.

## Layout and build
- Source: src/sim.js (pure game logic, node-testable), src/textures.js (texture slots, lab, banner tint), src/ui.js (render/input/HUD), src/template.html, src/build.py.
- Build: `cd src && python3 build.py && mv index.html ../index.html`. index.html at repo root is the built single file; always rebuild before committing source changes.
- Assets: assets/name_1..4.png (building views), see TEXTURE_SPEC.md and BUILDING_TILE_GUIDE.md. Art check: `python3 tools/check_textures.py` (buildings, plus ground tiles grass_N / grassfert_N).
- HUD: top bar is compact (resources show icon + number, hover for names); Banner/Textures/Drafting/Save/New live in the Menu dropdown; Goals is a one-line chip (click to expand); the left info panel only shows when hovering/pinning a tile or after pressing the ? button (welcome text shows once for brand-new players).
- Ground tile source art must be a 2048 x 1024 canvas (exactly 2:1) with the diamond corners on the edge midpoints; the loader scales by width, so a 3:2 diamond would be too tall. Edge band ~2 game px stays plain base colour so tiles blend.
- Design plan for terrain/lumber/ore/workforce: DESIGN_TERRAIN.md (status line at the top says what is built).
- Commit messages end with the attribution lines the session gives.

## Conventions that must not break
- Iso 2:1, tile diamond 32x16. Sprites: 1x1 32x48, 2x2 64x88, 3x3 96x128. Height is free. Hut (1x1) at most 28 px wide.
- View order for every building: _1 door lower-left, _2 upper-left, _3 upper-right, _4 lower-right. World face f: 0=+y,1=-x,2=-y,3=+x; sprite view = (ROT + b.face) % 4. 4-way camera rotation (Q/E).
- Buildings grow only on zone tiles touching a Hall-connected road; doors face the road. Town Hall is 3x3, barracks 2x2.
- Zone overlay is hidden under built tiles. Huts have sticky b.var (1..8) that never matches the 8 neighbouring houses.
- Forests: nothing can be built, zoned (except Lumber) or roaded on a tree tile (hasTree/TREE_MSG in sim.js); woodcutters clear land first. Each tree has a species (TREE_SPECIES in sim.js: broadleaf/oak 0,1,6 | conifer 2,3,7 | birch/aspen 4,9 | willow 5 | maple 8) chosen from low-frequency noise so neighbours share a species in patches (about 12% odd ones out), and a random variation within it; treeVariant(S,x,y) is derived from position and seed, so it is not saved. Oak and conifer tiles in thick forest are drawn as groves of 2-4 trees (treeGrove in sim.js picks the count from nearby tree density; art slots tree_oak_N and tree_pine_N, N=2..4; falls back to the single tree if the art is missing). keyOut also clears enclosed magenta pockets (gaps inside grove art).
- Lumber chain: Lumber zone marks trees; woodcutters fell marked trees into logs (S.res.logs); sawmill turns logs into wood; Town Hall pit-saws at half yield; felled tile -> stump -> grass. Mining zone marks rock. Stone and ore are FINITE and never regenerate: every rock tile has a reserve (S.dig = taken so far; mountain MOUNT_CAP 120, hill 50, rubble 40, DIG_U 10 per level), every ore tile holds ORE_CAP 30 (S.oreLeft), and a quarry/mine only takes what is really in the ground (mineRock/mineOre in sim.js; a full stockpile pauses them). Mountain (rockAmt 3) is permanent and solid (no buildings, zones or roads, no bulldozing): mining only HOLLOWS it (rockHollow 0..1 drawn as a growing cave) and when its reserve is gone it stays as a worked-out shell. Hills/rubble dig down level by level: hill -> rubble -> flat (buildable) -> pit 1..3 (rockLevel; pits are solid, cannot be built on, bulldozed or refilled, and joined pits render as one big hole). A mountain tile is only workable where it touches open ground or a worked-out mountain tile (rockOpen), so quarries cut inward. Mined-out ore tiles simply disappear. TERRAIN HEIGHTS: the ground is a grid of integer vertex heights S.hv ((N+1)^2, levels -8..8, 0 = base ground, LVL_PX=7 px per level); tileCorners/tileLevel/tileSpread/tileFlat in sim.js. Hills reach level 3 (broad rolling noise), basins dip to -1/-2 (no water yet), mountains reach 8. A tile whose average level is 4+ is mountain (rockAmt 3, solid, quarry only; S.elev = level*8 scales its stone). Tiles with 3+ levels of spread are too steep to build on (isSolid). Roads follow slopes (drawn bent over the slope); every other building builds UP the slope: its footprint is raised to its highest corner, never dug down (levelFootprint + relaxHeights keep neighbouring vertices within 1 level, 2 on high ground). Stone outcrops (rockAmt 1/2 on flat tiles) are the main stone supply besides mountains. Mountains are RARE (about 3% of the map): usually one range (ridge with several summits and saddles) plus maybe one lone massif, generated by mountainLayout/mountainField/genHeights. DESIGN INTENT: terrain shapes base layout and, once combat exists, attacks: you cannot climb straight up a mountain. walkCost(S,x,y,nx,ny) in sim.js is the movement rule (blocked into/over mountains and steep tiles or when levels differ by 2+, slopes cost extra); saddles between summits are the passes. Rendering (ui.js): ground sprites are draped over the slope (drape/groundDraw/geo), mountains are one continuous rock surface (terrainSprite), picking in screenToTile tests height levels so the right tile is hovered on hills. Old saves without S.hv get heights derived (deriveHeights); 40x40 saves are centred by growSave. Map is N=64 (START=32 is the Hall's centre); old 40x40 saves are centred into it by growSave() on load. Zoom ladder 0.5/1/2/3/4/5 (ZOOMS in ui.js); 0.5 shows nearly the whole map. Snow above ~44 px. Ore still works the old way (underground rework planned).
- Saves: localStorage 'thornwick-save-1', loadWorld migrates old saves (S.v2 flag). Never break loading old saves.

## How to test
- Sim tests: node scripts that load src/sim.js (see git history for tests, or write a short node script with `new Function('module','exports',code)`). Keep food topped up in long runs or the town starves.
- Visual: Playwright with /usr/bin/google-chrome (`--no-sandbox --allow-file-access-from-files`), page `file:///home/claude/thornwick-repo/index.html`, globals: setRot, setScale, centerOn, addBld, recalc, __game (S, zone, tick, place). Screenshot and look before claiming UI works. "Failed to load resource" console errors from asset probing are normal.
- Art review method: compare with the previous commit's sprite side by side at 4-6x with the footprint diamond overlaid, run the checker, render in game.

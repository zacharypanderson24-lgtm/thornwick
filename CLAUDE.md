# Thornwick: notes for Claude (read this first in every new chat)

Medieval TheoTown-style pixel isometric city builder. Owner: Zach. Hosted from this repo on GitHub Pages and Vercel (https://thornwick-two.vercel.app/, auto-deploys on push to main). ChatGPT makes the art (rules in CHATGPT_START_HERE.md); Claude does the code and reviews the art.

## Layout and build
- Source: src/sim.js (pure game logic, node-testable), src/textures.js (texture slots, lab, banner tint), src/ui.js (render/input/HUD), src/template.html, src/build.py.
- Build: `cd src && python3 build.py && mv index.html ../index.html`. index.html at repo root is the built single file; always rebuild before committing source changes.
- Assets: assets/name_1..4.png (building views), see TEXTURE_SPEC.md and BUILDING_TILE_GUIDE.md. Art check: `python3 tools/check_textures.py` (buildings, plus ground tiles grass_N / grassfert_N). Pink check: `python3 tools/check_no_pink.py` fails on ANY pink, magenta or purple pixel left in any assets/*.png after the game's background removal (flood fill from the edges plus enclosed magenta pockets); a GitHub Action (.github/workflows/textures.yml) runs it on every push and pull request touching assets/ or tools/. It has no allowlist on purpose. To fix failures automatically run `python3 tools/clean_pink.py`, which makes the stray pixels see-through (flat magenta in RGB files, alpha 0 in files that have alpha).
- WORKFORCE (built): recalc() in sim.js fills jobs by trade priority (TRADES / TRADE_OF; default farming, timber, woodwork, quarrying, mining, trade; S.prio overrides and is saved), giving every job building its own b.workers and b.eff (= workers / jobs, derived each recalc, not authoritative in saves). Output in tick() and computeDemand() scales with each building's b.eff, never with one global ratio; d.work[trade] = {workers, jobs, blds, short}, d.employed, d.idle, d.mkEff. The Workers button in the HUD opens the Workforce panel (renderWork in ui.js): rows in priority order with up/down buttons, click a row to light that trade's buildings on the map (red when short). Tests: /tmp-style node script, see git history for work_test.
- BOTTOM BAR (TheoTown style): Look (1), Build (B), Zone (Z), Clear (0). Build and Zone open a flyout above the bar (#flyout, openCat/toggleCat/showCat/setTool in ui.js). Build = construction you place one at a time (road 2, well 8, sawmill X, forester F, barracks 9); Zone = painted areas where buildings grow (housing 3, farmland 4, commerce 5, lumber 6, mining 7). TOOLS entries carry `cat: 'build'|'zone'`; add new tools there and they land in the right flyout. Pressing a tool's hotkey opens its flyout; Esc, Look or Clear close it.
- HUD: top bar is compact (resources show icon + number, hover for names); Banner/Textures/Drafting/Save/New live in the Menu dropdown; Goals is a one-line chip (click to expand); the left info panel only shows when hovering/pinning a tile or after pressing the ? button (welcome text shows once for brand-new players).
- Ground tile source art must be a 2048 x 1024 canvas (exactly 2:1) with the diamond corners on the edge midpoints; the loader scales by width, so a 3:2 diamond would be too tall. Edge band ~2 game px stays plain base colour so tiles blend.
- Design plan for terrain/lumber/ore/workforce: DESIGN_TERRAIN.md (status line at the top says what is built).
- Commit messages end with the attribution lines the session gives.
- Props rule (Zach's rule, in CHATGPT_START_HERE.md and BUILDING_TILE_GUIDE.md): walls sit on the footprint diamond, but props (barrels, crates, steps, poles...) may stand outside the building and past the diamond, as long as the whole sprite stays inside the green box / picture width. check_textures.py's base-vs-diamond check may flag such props on 2x2/3x3 buildings; judge those by eye.
- Directional coherence (Zach's rule, in CHATGPT_START_HERE.md and BUILDING_TILE_GUIDE.md rule 9): features belong to fixed walls (W1 door wall, W2 right of it in view 1, W3 opposite W1, W4 opposite W2) and show only in views where that wall faces the camera (v1 W1+W2, v2 W2+W3, v3 W3+W4, v4 W4+W1). When reviewing art, flag windows/props that appear on the wrong side or vanish when their wall is visible.
- Backgrounds (Zach's rule, docs updated): new textures use a TRANSPARENT background (real PNG alpha, alpha 0 or 255 only), not magenta. The game already handles both: keyOut in textures.js skips images whose corners are transparent, and flat magenta still gets keyed out, so old assets keep working; check_no_pink.py and check_textures.py accept transparent. The footprint guide templates in templates/ keep their magenta background; they are only guides.
- Art priority (Zach's rule, also in CHATGPT_START_HERE.md): textures must be usable game assets at their real sizes; never produce fancy, higher-resolution or unusable showpiece renditions.

## Conventions that must not break
- Iso 2:1, tile diamond 32x16. Sprites: 1x1 32x48, 2x2 64x88, 3x3 96x128. Height is free. Hut (1x1) at most 28 px wide.
- View order for every building: _1 door lower-left, _2 upper-left, _3 upper-right, _4 lower-right. World face f: 0=+y,1=-x,2=-y,3=+x; sprite view = (ROT + b.face) % 4. 4-way camera rotation (Q/E).
- Buildings grow only on zone tiles touching a Hall-connected road; doors face the road. Town Hall is 3x3, barracks 2x2.
- Zone overlay is hidden under built tiles. Huts have sticky b.var (1..8) that never matches the 8 neighbouring houses.
- Forests: nothing can be built, zoned (except Lumber) or roaded on a tree tile (hasTree/TREE_MSG in sim.js); woodcutters clear land first. Each tree has a species (TREE_SPECIES in sim.js: broadleaf/oak 0,6,6 (tree_1 is retired, its art was off-style: flat and outline-free; tree_6 old oak takes its share, so the list repeats 6; tree_1 stays a slot but is never picked) | conifer 2,3,7 | birch/aspen 4,9 | willow 5 | maple 8) chosen from low-frequency noise so neighbours share a species in patches (about 12% odd ones out), and a random variation within it; treeVariant(S,x,y) is derived from position and seed, so it is not saved. Every tree variant can be drawn as a grove of 2-4 trees of its own kind (TREE_GROVE_ART + treeGrove in sim.js; the count comes from nearby tree density; art slots tree_oak_N, tree_old_oak_N, tree_pine_N, tree_spruce_N, tree_fir_N, tree_birch_N, tree_willow_N, tree_maple_N, tree_aspen_N, N=2..4; falls back to the single tree if the art is missing). keyOut also clears enclosed magenta pockets (gaps inside grove art).
- WORK CREWS (built; Zach's rule: workers live at their building and commute): woodcutters (now named Woodcutter Lodge), quarries and iron mines have worker agents, one per b.workers, in sim.js (CREW WeakMap, crewOf(b), stepCrews, crewTarget, crewAct; runtime only, NEVER saved, everyone starts at home after load). States: home (resting inside, not drawn) -> out (walking, BFS over walkCost-passable tiles, roads and own building allowed, depth 10) -> work (WORK_T=2 days at a tile beside the marked tree/rock/ore, never on the building's own tile) -> back (carrying a load) -> deliver at the building. Output only comes from delivered loads: LOAD wood 6 / quarry 5 / mine 4; a tree takes CHOPS_PER_TREE=4 chops (S.chop, saved, 24 logs) before it becomes a stump; rock/ore come from mineRock/mineOre at the target tile (r=0). Nearer sites make faster trips (cycle about 2*steps+4 days); balance was matched to the old rates (about 0.8 logs, 0.7 stone, 0.55 ore per worker per day at 2 tiles). Full stockpile keeps quarry/mine crews home; no marked tile in WORK_R=3 (reachable) keeps them home. HUD rates for logs/stone/ore are smoothed (EMA) because loads arrive in lumps. Drawing: ui.js buckets moving agents per nearest tile (crewAt) and draws SPR.worker (6x10 code-drawn villagers, tinted by trade, carrying marker when heading home), position lerped with tickFrac; skipped at LOD. Info panel shows crewLine(b).
- Lumber chain: Lumber zone marks trees; woodcutters fell marked trees into logs (S.res.logs); sawmill turns logs into wood; Town Hall pit-saws at half yield; felled tile -> stump -> grass. FORESTERS (built, key F, 8 wood, 2 jobs, trade 'timber'): Lumber zones can now also be painted on open flat-ish ground (zoneCheck allows tree, sapling, stump or empty tile with spread < 2). A forester plants one sapling per PLANT_EVERY=4 days at full staffing on the nearest open Lumber-zone tile within FORESTER_R=4 (plantSapling in sim.js); deco 'sapling' (S.sapT = days left, SAPLING_DAYS=1095 (3 years of 365 days; the game has no calendar, 1 day = 1 s at 1x), saved; old saves without it load fine) grows into 'tree'. hasTree() counts saplings so nothing can be built on them. fellTree keeps the Lumber zone on the felled tile only if a forester covers it (foresterCovers); otherwise it is cleared as before, so woodcutter-only play is unchanged. Sprites are code-drawn (SPR.forester, SPR.sapling); a 'forester' texture slot exists for ChatGPT art. Mining zone marks rock. Stone and ore are FINITE and never regenerate: every rock tile has a reserve (S.dig = taken so far; mountain MOUNT_CAP 120, hill 50, rubble 40, DIG_U 10 per level), every ore tile holds ORE_CAP 30 (S.oreLeft), and a quarry/mine only takes what is really in the ground (mineRock/mineOre in sim.js; a full stockpile pauses them). Mountain (rockAmt 3) is permanent and solid (no buildings, zones or roads, no bulldozing): mining only HOLLOWS it (rockHollow 0..1 drawn as a growing cave) and when its reserve is gone it stays as a worked-out shell. Hills/rubble dig down level by level: hill -> rubble -> flat (buildable) -> pit 1..3 (rockLevel; pits are solid, cannot be built on, bulldozed or refilled, and joined pits render as one big hole). A mountain tile is only workable where it touches open ground or a worked-out mountain tile (rockOpen), so quarries cut inward. Mined-out ore tiles simply disappear. TERRAIN HEIGHTS: the ground is a grid of integer vertex heights S.hv ((N+1)^2, levels -8..8, 0 = base ground, LVL_PX=7 px per level); tileCorners/tileLevel/tileSpread/tileFlat in sim.js. Hills reach level 3 (broad rolling noise), basins dip to -1/-2 (no water yet), mountains reach 8. A tile whose average level is 4+ is mountain (rockAmt 3, solid, quarry only; S.elev = level*8 scales its stone). Tiles with 3+ levels of spread are too steep to build on (isSolid). Roads follow slopes (drawn bent over the slope); every other building builds UP the slope: its footprint is raised to its highest corner, never dug down (levelFootprint + relaxHeights keep neighbouring vertices within 1 level, 2 on high ground). Stone outcrops (rockAmt 1/2 on flat tiles) are the main stone supply besides mountains. Mountains are RARE (about 3% of the map): usually one range (ridge with several summits and saddles) plus maybe one lone massif, generated by mountainLayout/mountainField/genHeights. DESIGN INTENT: terrain shapes base layout and, once combat exists, attacks: you cannot climb straight up a mountain. walkCost(S,x,y,nx,ny) in sim.js is the movement rule (blocked into/over mountains and steep tiles or when levels differ by 2+, slopes cost extra); saddles between summits are the passes. Rendering (ui.js): ground sprites are draped over the slope (drape/groundDraw/geo), mountains are one continuous rock surface (terrainSprite), picking in screenToTile tests height levels so the right tile is hovered on hills. Old saves without S.hv get heights derived (deriveHeights); 40x40 saves are centred by growSave. Map is N=64 (START=32 is the Hall's centre); old 40x40 saves are centred into it by growSave() on load. Zoom ladder 0.5/1/2/3/4/5 (ZOOMS in ui.js); 0.5 shows nearly the whole map. PERFORMANCE: at scale <= 0.5 draw() uses a LOD: the whole map's ground (grass, zones, fully slope-draped) comes from one cached layer (groundLayer/groundSig in ui.js, rebuilt only when zones, fertility, rock, heights or rotation change), tree groves and warning icons are skipped; per-tile vertical lift is a plain y offset (never ctx.translate per tile, it was the main cost). drawImage count is the cost driver, so keep per-tile draw calls down. Snow above ~44 px. Ore still works the old way (underground rework planned).
- Saves: localStorage 'thornwick-save-1', loadWorld migrates old saves (S.v2 flag). Never break loading old saves.

## How to test
- Sim tests: node scripts that load src/sim.js (see git history for tests, or write a short node script with `new Function('module','exports',code)`). Keep food topped up in long runs or the town starves.
- Visual: Playwright with /usr/bin/google-chrome (`--no-sandbox --allow-file-access-from-files`), page `file:///home/claude/thornwick-repo/index.html`, globals: setRot, setScale, centerOn, addBld, recalc, __game (S, zone, tick, place). Screenshot and look before claiming UI works. "Failed to load resource" console errors from asset probing are normal.
- Art review method: compare with the previous commit's sprite side by side at 4-6x with the footprint diamond overlaid, run the checker, render in game.
